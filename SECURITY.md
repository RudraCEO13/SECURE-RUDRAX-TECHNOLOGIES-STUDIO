## Reporting a Vulnerability

At **RudraX Technologies Studio™**, we take the security and integrity of our software, platforms, and user data extremely seriously. If you believe you have discovered a security vulnerability, flaw, or potential bug within any of our applications, web services, codebases, or APIs, we strongly encourage you to notify us immediately.

### Responsible Disclosure Guidelines

To help us process and resolve security reports efficiently, please adhere to the following reporting guidelines:

1. **Direct Communication:** Please **do not** create public GitHub issues, forum posts, or public social media threads for security vulnerabilities. Report all issues privately via email.
2. **Dedicated Security Contact:** Send a detailed security advisory directly to our administrative team at:
   * **Primary Security Email:** `rudraxtechnologiesstudio@gmail.com`
   * **Secondary Contact:** `rudrapurparmar@gmail.com`
3. **Required Information:** To assist our evaluation process, please include as much of the following information as possible in your report:
   * A clear and concise description of the security vulnerability.
   * Steps to reproduce the issue (including proof-of-concept scripts, HTTP requests, or screenshots if applicable).
   * Affected components, repositories, endpoints, or software version numbers.
   * Potential impact of the vulnerability if exploited.

---

## Response & Patch Policy

Upon receiving a security vulnerability report, **RudraX Technologies Studio™** commits to the following timeline:

* **Acknowledgment:** We will acknowledge receipt of your vulnerability report within **48 hours**.
* **Assessment & Verification:** Our core technical team will evaluate and reproduce the reported issue within **3 to 5 business days**.
* **Remediation & Patching:** If validated, a security patch or mitigation update will be developed and deployed as a high-priority release.
* **Public Disclosure:** Once the vulnerability is fully patched, public release notes or security advisories may be published with proper credit given to the reporting researcher (if requested).

---

## Safe Harbor Statement

If you conduct security research and report vulnerabilities in good faith and in compliance with this Security Policy:

* We will consider your research activities authorized and legitimate.
* We will not pursue legal action against researchers for accidental, good-faith violations of privacy or service availability during responsible security testing.
* We ask that you give us reasonable time to address and patch reported vulnerabilities before making any public disclosures.
